# 面向自组网的多路径 DSDV 与图神经网络多智能体路由调度研究

## 研究设计报告

> 说明：本报告说明拟开展的研究工作，包括研究目标、技术路线、总体架构与方法设计。
> 报告只陈述设计思路与机制，不涉及性能结论，也不包含实现层面的代码细节。
> 文中关于已有工作的判断均标注来源，参考文献编号见第九节；完整综述见第七节。

## 一、研究目标与研究问题

### 1.1 总体目标

以 DSDV 为信息基础设施，构建一条从"协议状态"到"结构化图观测"再到"多路径流量分配"的完整通路，并在此之上训练一套分布式协作调度策略，使节点在动态拓扑下能够利用多条可用路径按比例分配流量。

具体由三个部分构成：

1. **协议侧的状态组织。** 在不改变协议转发语义的前提下，扩充 DSDV 的路由表使其为每个目的维护多条候选路径；新增一个周期性的状态广播，交换"自身节点状态 + 一跳邻居的节点状态 + 自身直连链路的跨层状态"；并把链路状态按物理层、介质访问层、网络层、路由层四个层次分别采集。
2. **节点级的图观测。** 每个节点以固定的决策周期，把上述状态组织成一张以自身为中心、恰好覆盖两跳的图：节点特征 6 维、边特征 4 维，候选动作集合直接取自多路径路由表。观测是策略网络的输入，候选集合是策略网络的动作空间。
3. **图策略与改进的协作学习框架。** 用两层图注意力网络把图观测映射为对各候选下一跳的流量分配比例；在集中训练、分散执行的框架下，用差分奖励改善各节点的信用分配，用拓扑感知的图价值网络改善价值估计。

### 1.2 问题背景（简述）

自组网拓扑随节点移动持续变化、链路质量频繁波动，且每个节点只掌握局部信息。传统协议以固定度量与固定规则转发：DSDV [1] 以跳数最优为准，AOMDV [2] 等多路径方案虽维护了多条路径，转发规则仍预先设定（如取剩余带宽最大者 [3]）。队列积压、链路利用率、帧交付率、链路稳定程度这些反映真实网络状态的时变量，原则上都可由节点在协议栈内测得，却未被纳入转发决策。

将路由建模为多智能体决策、用图神经网络（GNN）编码拓扑、用强化学习学习策略，是近年的一条主要路线（如 [6][12]）。但据本项目前期的文献梳理，这些工作在观测设计、动作粒度、多跳信息的获取方式、协作学习的信用分配等方面仍存在若干局限，**详细综述与逐条依据见第七节**。本文正是针对这些问题，在主动式协议之上构建上述通路。

### 1.3 三个研究问题

> **RQ1（观测问题）**：能否仅利用主动式路由协议在运行过程中本就可获得的信息——路由表条目、节点队列状态、以及协议栈内可测的物理层、介质访问层、网络层、路由层链路统计——为每个节点构建一张以自身为中心、范围恰好覆盖两跳、并与策略网络的感受野一致的结构化图观测，使得节点在不依赖定位、不依赖全局视图、不进行嵌入交换的前提下获得充分的状态表征？

> **RQ2（决策问题）**：在上述观测所对应的、由多路径候选下一跳构成的动态动作空间上，图注意力策略能否学习"对各候选下一跳按比例分配流量"的决策，并适应节点数目与邻居数目变化的图？

> **RQ3（学习问题）**：面向多个节点的协作调度，以差分奖励替代统一的全局奖励、以拓扑感知的图价值网络替代与拓扑无关的价值估计，能否使各节点获得更贴近自身边际贡献的学习信号与更准确的价值估计？

三个问题分别对应第七节所归纳的既有工作局限，映射关系见 7.6。

### 1.4 研究边界

- 本文不以"设计一个新协议在路由性能上取代 DSDV"为目标，也不在协议内部做复杂的路径度量优化；
- 协议侧的改动只服务于**信息收集与存储**，以及为策略提供**候选下一跳集合**；是否使用某条路径、如何使用，交由学习得到的策略决定；
- 本文的重点是**观测机制的设计**、**策略网络的拓扑泛化能力**、以及**面向协作调度的学习框架改进**，而非单点性能指标的最优。

## 二、技术路线：输入、输出与做法

### 2.1 系统的输入与输出

**策略网络的输入（每个节点在每个决策周期）。** 对节点 $i$ 在第 $t$ 个决策周期，输入为一个图观测与一个候选动作集合：

$$G_i(t)=\bigl(V_i,\; X_i,\; E_i,\; X^{e}_i\bigr),\qquad C_i(t)\subseteq V_i$$

其中：

| 符号 | 含义 | 内容 |
|---|---|---|
| $V_i$ | 观测图中的节点集合 | 节点 $i$ 自身、其全部一跳邻居、以及可发现的两跳邻居 |
| $X_i$ | 节点特征 | $|V_i|\times 6$，6 维含义见 2.2 |
| $E_i$ | 边集合 | 自身到各一跳邻居的边，以及各一跳邻居到其邻居的边 |
| $X^{e}_i$ | 边特征 | $|E_i|\times 4$，4 维含义见 2.2 |
| $C_i(t)$ | 候选动作集合 | 来自多路径路由表的候选下一跳，即策略可选的动作 |

**策略网络的输出（每个节点在每个决策周期）。** 节点 $i$ 输出其对候选集合中各下一跳的流量分配比例：

$$a_i(t)=\bigl(p_{i1},p_{i2},\dots,p_{i|C_i|}\bigr),\qquad p_{ik}\ge 0,\quad \sum_{k} p_{ik}=1$$

即：节点 $i$ 把当前待转发的数据按该比例分配给候选下一跳。当候选集合中只有一个元素时，输出退化为"全部走该下一跳"，与协议原有行为一致。

**环境反馈与学习信号。** 协议按分配比例执行转发后，由网络统计得到全局奖励（吞吐量、平均时延、丢包率等指标的加权组合）；再以差分形式得到节点级的学习信号（见 4.4）；观测序列、动作序列与节点级奖励共同构成训练轨迹，用于更新策略与价值网络。

**训练与执行的区别。** 训练阶段价值网络可以访问全局图信息（集中训练）；执行阶段每个节点只使用自身的图观测与本地策略（分散执行），节点之间不需要交换嵌入或同步全局视图。

### 2.2 图观测的两个特征集合

**节点特征（6 维）。**

| 维度 | 含义 | 数据来源 |
|---|---|---|
| 队列占用率 | 本地待转发数据的积压程度 | 本节点队列状态 |
| 一跳邻居数 | 直接可达邻居个数 | 协议路由表中的一跳条目 |
| 两跳邻居数 | 经邻居可发现的更远节点个数 | 邻居广播的链路信息 |
| 本地转发负载 | 本节点近期转发量相对链路容量的比例 | 本节点转发统计 |
| 邻居平均队列占用率 | 近邻的平均拥塞程度 | 邻居广播的节点状态 |
| 到各目的的平均可用路径数 | 多路径的丰富程度 | 多路径路由表 |

**边特征（4 维，按采集层次区分）。**

| 维度 | 含义 | 采集层次 |
|---|---|---|
| 链路质量 | 物理层信噪比的归一化结果 | 物理层 |
| 链路利用率 | 近期转发字节数与链路速率之比 | 网络层 |
| 链路可靠性 | 介质访问层帧发送的成功比例 | MAC 层 |
| 链路稳定性 | 该邻居在路由表中持续可达的时间占比 | 路由层 |

把上述四维放在**边**上是本设计的关键选择：路由决策的差异往往不在"哪个节点更好"，而在"经由哪条链路更好"。仅以跳数作为度量时，跳数相同但质量不同的两条路径无法区分；而上述四维恰好从物理、MAC、网络、路由四个层面刻画了链路状态，且全部来自协议栈运行过程中自然产生的统计量，不需要额外的探测机制。

### 2.3 技术路线：输入 → 处理 → 输出

整个方法分为五个步骤，每一步的输入、处理方式与输出如下。

| 步骤 | 输入 | 处理方式 | 输出 |
|---|---|---|---|
| **① 观测生成** | 多路径路由表；邻居状态存储；本节点的队列与转发统计；跨层链路统计 | 以本节点为中心确定"自身 + 一跳 + 两跳"节点集合；按 2.2 为每个节点构造 6 维特征、为每条边构造 4 维特征；汇总各活跃目的的候选下一跳 | 图观测 $G_i(t)$ 与候选集合 $C_i(t)$ |
| **② 图编码** | $G_i(t)$ | 两层图注意力消息传递：第一层把两跳节点的信息聚合到一跳节点，第二层再聚合到中心节点；**边特征参与注意力权重的计算**，质量差或拥塞的邻居其信息被相应弱化 | 中心节点的嵌入表示，以及各候选下一跳的边表征 |
| **③ 决策** | 中心节点嵌入 + 各候选下一跳的边表征 | 将中心嵌入与各候选的链路状态结合，并做归一化 | 流量分配比例 $a_i(t)$ |
| **④ 执行与反馈** | $a_i(t)$ | 协议按比例把待转发数据分给候选下一跳；统计吞吐、时延、丢包、控制开销 | 全局奖励；按差分形式得到的节点级奖励（见 4.4） |
| **⑤ 学习更新** | 轨迹 $\{(G_i(t), a_i(t), r_i(t))\}$ | 广义优势估计；PPO 的裁剪目标更新策略网络；价值网络在整张图上做消息传递并以图级聚合输出全局价值；熵正则维持探索 | 更新后的策略网络与价值网络参数 |

配套的闭环数据流为：

```
协议状态 ──► 图观测 G_i(t) ──► 图策略网络 ──► 流量分配比例 a_i(t)
   ▲                                                    │
   │                                                    ▼
   └──── 策略更新 ◄── 学习框架 ◄── 节点级奖励 r_i(t) ◄── 协议按比例转发 ◄── 网络统计
```

### 2.4 三项核心方法概述

**（1）协议侧：多路径候选的被动维护。** 节点在周期性路由更新中仍只广播自己到各目的的最优路径信息，不额外暴露备份路径；接收方发现同一目的存在经不同下一跳、且跳数不超过最优值加一个容差的路径时，将其登记为候选。约束为：每目的最多保留固定条数；各候选下一跳互不相同；只保留与最优路径质量相近的路径。该机制不决定走哪条路，只保证候选集合随时可用，作为策略的动作空间。

**（2）观测侧：恰好两跳的图观测。** 观测范围设为两跳，是因为策略网络使用两层消息传递——第一层把两跳节点的信息聚合到一跳节点，第二层再聚合到中心节点，中心节点所能"看到"的范围正好等于观测提供的两跳邻域，**观测范围与网络深度严格对应**。观测所需信息由周期性的状态广播提供，任一节点掌握的信息恰好覆盖两跳（详见 4.1、4.3）。

**（3）学习侧：改进的多智能体 PPO。** 在集中训练、分散执行的基础上，用**差分奖励**以节点采取基线动作时的全局奖励为对照，近似刻画其边际贡献；用**拓扑感知的图价值网络**在整张图上做消息传递与图级聚合，使价值估计反映拓扑结构及其扰动。

## 三、系统总体架构

### 3.1 分层架构

系统分为三层：**协议与仿真层**、**桥接层**、**学习层**。

```
┌──────────────────────────────────────────────────────────────────────┐
│                          学习层（Python）                              │
│                                                                        │
│   图构建 ──► 图策略网络（Actor）──► 流量分配比例                        │
│      ▲                │                                                │
│      │                ▼                                                │
│   图观测          拓扑感知价值网络（Critic）──► 全局价值估计             │
│      │                │                                                │
│      │                ▼                                                │
│      └──────── MAPPO 更新（策略梯度 + 价值回归 + 熵正则）                │
│                                                                        │
│   训练：集中（价值网络可见全局图）；执行：分散（各节点只用本地观测）        │
└──────────────────────────────────────────────────────────────────────┘
             ▲  观测（每 10ms）            │  动作：流量分配比例（每 10ms）
             │                             ▼
┌──────────────────────────────────────────────────────────────────────┐
│                        桥接层（共享内存）                               │
│   以本节点为中心的图观测（节点特征/边索引/边特征/多路径候选）             │
│   与策略输出（对各候选下一跳的分配比例）双向传递，低时延、无网络开销        │
└──────────────────────────────────────────────────────────────────────┘
             ▲                             │
             │                             ▼
┌──────────────────────────────────────────────────────────────────────┐
│                     协议与仿真层（ns-3，主动式路由协议）                  │
│                                                                        │
│   路由表（多路径）      特征存储（邻居与其近邻状态、直连链路状态）          │
│        │                        │                                      │
│        └────────┬───────────────┘                                      │
│                 ▼                                                      │
│        以本节点为中心的图观测构建（自身 + 一跳 + 两跳）                   │
│                                                                        │
│   无线信道 / MAC / 队列 / 移动性 / 流量  ──►  网络统计（吞吐、时延、丢包） │
└──────────────────────────────────────────────────────────────────────┘
```

**为什么采用 ns-3 与 Python 联合仿真。** 网络侧的无线信道、介质访问、队列与移动性需要包级的高保真建模，由 ns-3 承担；策略网络的表征与学习由深度学习与图学习框架承担。二者通过共享内存直接交换数据，而不经网络协议通信，避免引入额外时延、也避免干扰仿真本身的离散事件时序。这种分工使策略是在**真实协议行为**之上学习，而不是在抽象图或静态数据上学习。

### 3.2 时间尺度

| 时间尺度 | 职责 | 设计理由 |
|---|---|---|
| 10 ms（决策周期） | 重建以本节点为中心的图观测；策略推理；按比例分配流量 | 队列与拓扑变化需在较细粒度上被跟踪，决策必须快于拓扑变化 |
| 1 s（状态交换周期） | 广播自身节点状态与链路状态，接收并存储邻居状态 | 邻居状态不必每 10 ms 交换一次；降低控制开销，同时保证观测足够新鲜 |
| 路由更新周期 | 交换到各目的的最优路径信息，多路径在此过程中被动获得 | 复用协议原有的周期更新，不引入额外控制包 |
| 事件驱动 | 链路断裂、新邻居加入时立即响应并受抑制地广播更新 | 拓扑突变需尽快收敛，同时避免广播风暴 |

三个尺度分离的意义在于：**决策频率高、状态交换频率低、控制开销可控**。策略每 10 ms 决策一次，但其依据的邻居状态以秒级刷新；"是否需要重新收敛路由"由协议的事件机制负责。

## 四、方法设计

### 4.1 协议侧：多路径候选的维护

设计原则：

1. **被动发现、零额外控制包**——多路径是在协议本来就要交换的信息中被顺带发现的，这一点与 HMP [3] 的思路一致，而与 MDSDV [4] 需要额外路由探测包的做法不同；
2. **第一跳不相交**——同一目的下各候选的下一跳必须不同；
3. **有界次优**——只保留跳数不超过最优路径加一个容差的路径，避免把质量明显更差的路径纳入动作空间；
4. **数量有界**——每目的最多保留固定条数，保证动作空间与观测规模可控；
5. **序列号优先**——更新的新旧仍由协议原有的序列号机制判定，保持原有的无环性质；
6. **主路径降级而非删除**——主路径切换时原主路径降级为候选，序列号推进时同步所有候选；
7. **事件驱动的状态一致**——链路断裂时删除经该邻居的所有路径并清除相关邻居状态，新邻居被发现时建立占位，两类事件均触发受抑制的路由更新。

### 4.2 观测侧：图观测的组装与动作空间的耦合

观测以固定的决策周期重建，形成节点特征矩阵、边索引、边特征矩阵以及多路径候选信息（每个活跃目的的主下一跳、各候选下一跳及其跳数）。因此拓扑变化、链路质量波动与队列变化都会在下一个决策周期反映到图上。

**动作空间不是预设的固定大小，而是从图中推导出来的**：候选动作就是中心节点在观测图中的出边，即当前可用的下一跳，并受多路径路由表的约束。这样，策略的每一个动作都天然落在"协议认为可行"的集合内，既避免了无效动作，也使动作空间随节点度数与候选路径数量自适应地变化。

### 4.3 观测信息的获取方式与传播边界

观测所需的信息通过周期性的状态广播获得（周期取 1 秒，并附加随机抖动以避免同时发送造成的碰撞）。每个节点广播的内容由三部分组成：

1. **自身的节点特征**；
2. **自身所有一跳邻居的节点特征**——这些是邻居此前广播给它、由它代为转发的；
3. **自身所有直连链路的四维特征**——由本节点自己测量。

传播的边界被刻意限定为：

- **传播**：本节点的自身状态、本节点实测的链路状态、本节点所掌握的一跳邻居的**节点**状态；
- **不传播**：邻居的**链路**状态、超出两跳范围的信息、以及路由表内容（后者由路由更新单独承担）。

由此，任一节点所掌握的信息恰好覆盖两跳：它从邻居的广播中得知邻居的邻居（即自己的两跳邻居）的节点状态与邻居侧的链路状态，但不会再向外扩散，第三跳的节点不会出现。这样既满足"观测范围与网络深度对应"的要求，也把控制开销限制在可控范围。

另有一处刻意的设计：**一跳邻居集合以路由表中的一跳条目为准，而不是以状态存储为准**。原因是某条链路在协议上已被确认可达，但其状态信息可能尚未到达（广播有周期）；若以状态存储为准，就会出现"明明可达却从观测中消失"的缺失。

### 4.4 学习侧：改进的多智能体 PPO

基础框架采用多智能体 PPO，核心是集中训练、分散执行：训练时价值网络可访问全局图信息以更准确地评估状态；执行时每个节点只使用自身局部观测与本地策略，节点之间不通信，符合自组网的分布式本质。在此基础上拟引入两项改进。

**改进一：以差分奖励改善信用分配。** 整网奖励由吞吐量、平均时延、丢包率等可加权的全局指标构成，衡量的是"整个网络做得好不好"。若把同一全局奖励不加区分地分配给所有节点，不承担中继的节点与承担大量中继的节点会获得相同的学习反馈，容易导致"搭便车"，不利于形成分工明确的协作策略。拟采用的形式是：以该节点采取**基线动作**（即协议默认的下一跳选择）时的全局奖励作为对照，用实际全局奖励与对照值之差作为该节点的学习信号，近似刻画其相对于"不作为"的边际贡献。

这一形式在原理上是清晰的，但实现上有一个关键问题需要在工作点三中解决：**反事实基线如何稳定获得**。可行思路包括在训练中周期性让某节点退回默认策略以观测对照结果，或以近似方式估计该基线。本报告不对其效果作提前判断。

**改进二：以拓扑感知的图价值网络替代固定的全局价值网络。** 若价值网络在一段固定维度的全局特征向量上估计价值，则在节点数改变、拓扑重构时不再适用，也难以体现拓扑结构本身对长期回报的影响。拟采用的价值网络在**整张图上**做消息传递，并通过图层面的聚合得到全局价值估计，从而既能反映拓扑结构及其扰动，又与图规模无关。

## 五、关键设计参数与设计取舍

### 5.1 关键参数

| 参数 | 取值 | 说明 |
|---|---|---|
| 每目的最大候选路径数 | 5（含主路径） | 控制动作空间与观测规模 |
| 候选路径的跳数容差 | 1 | 只保留与最优路径质量相近的路径 |
| 决策与观测周期 | 10 ms | 跟踪队列与拓扑变化的细粒度 |
| 状态广播周期 | 1 s（含毫秒级抖动） | 邻居状态的刷新频率；抖动避免同时发送造成碰撞 |
| 路由更新周期 | 仿真阶段取较密的值，正式配置回到协议默认量级 | 决定多路径被发现的速度 |
| 观测范围 | 两跳 | 与两层消息传递的感受野一致 |
| 目标网络规模 | 20–50 节点 | 本工作的目标场景规模 |

### 5.2 主要设计取舍

- **为什么以 DSDV 为基础。** 它是表驱动协议，任意时刻都持有到全网的路由表，因此**任意时刻都有可用的图观测**；它是距离矢量协议，结构简单、改动影响范围清晰；它本身周期性交换信息，天然可以承载状态广播；实现规模适中，便于完整掌握与修改。
- **为什么观测只到两跳。** 观测范围越大，控制开销越高，且自组网无中心节点、全局同步代价高。两跳既与策略网络的深度匹配，又足以让节点感知邻居的拥塞与链路质量，是信息量与开销之间的折中；超出两跳的信息由策略的逐跳协作隐式传播。
- **为什么动作是流量分配比例而不是单一的下一跳选择。** 选择单跳无法利用多路径做负载均衡；比例分配可以表达"主路径承担大部分流量、备份路径分担其余流量"这类更细腻的策略，避免主路径拥塞时整条流一起劣化；同时，连续的比例动作空间比离散选择更适合用策略梯度方法直接优化，也更容易定义差分奖励所需的"回到基线动作"。
- **为什么采用 PPO 类方法而非值函数类方法。** 输出是连续的比例向量，直接在策略分布上做梯度更新更为自然；PPO 的裁剪机制在训练稳定性上较为成熟；多智能体 PPO 提供了现成的集中训练—分散执行框架，便于承载上述两项改进。
- **为什么不在观测中使用位置信息。** 位置信息需要额外硬件支持，且在室内或受扰环境中未必可靠；本工作所用特征全部来自协议栈自身的测量，不依赖定位，更贴近真实自组网的约束。

为说明方案的可行性基础，此处如实说明已经完成与尚在推进的部分。本报告不对任何性能作结论。

- 联合仿真链路：仿真器与学习进程之间的共享内存通道已建立，观测可以下发、动作可以回传；

**尚在推进的部分：**

- 图策略网络与拓扑感知图价值网络的实现与接入；

- 完整训练流程，以及在多种拓扑、规模与流量条件下的对比与消融评估。

上述划分说明：本工作目前处于"观测机制与系统链路已具备、学习算法尚在实现"的阶段。

## 七、相关工作与本文定位

### 7.1 多路径路由

多路径的思想在传统协议中已有较长的研究历史。AOMDV [2] 扩展按需式路由发现过程，通过一次请求/应答过程收集多条互不相交的路径，并可选链路不相交或节点不相交约束；其代价是路由发现阶段泛洪开销较大，且首次通信存在发现时延。在主动式一侧，HMP [3] 直接改造 DSDV 的路由表，使每个目的保留所有"最小跳数"的下一跳，并在邻居表中维护剩余带宽，转发时选择剩余带宽最大的下一跳，**不引入任何额外的控制包**；MDSDV [4] 则在 DSDV 之上让源节点在需要通信时发送路由探测包，收集邻居反馈后组装多条第一跳不相交的路径，以跳数最短者为主路径。这些工作说明：**在主动式协议上低成本地获得多条候选路径是可行的**，但其转发规则仍然是预先设定的（如"取剩余带宽最大者""取跳数最短者"），路径的取舍不随网络状态的长期演化而调整。

### 7.2 基于图神经网络与强化学习的路由

Mai 等 [6] 将每个路由器视为一个智能体，用图注意力网络聚合邻居信息，观测为队列长度、邻居数、已服务包数与平均等待时间四项标量，动作为**从邻居中离散地选择一个下一跳**，用参数共享的多智能体 PPO 训练，奖励由全局吞吐量与局部成功转发数构成；其图结构固定，且只使用一跳邻居。Ding 等 [7] 用独立的 DQN 学习拥塞下的路由，观测为本地队列、各邻居队列与各邻居链路利用率，动作为**取 Q 值最大的邻居**。GAPPO [8] 用图注意力编码当前网络拓扑并由 PPO 更新，重点考察链路故障与拓扑突变下的鲁棒性，并在多种网络规模上训练；Geyer 与 Carle [9] 则用 GNN 直接学习一个分布式路由协议的行为，输入为邻居的转发表信息、输出为本节点的转发表更新，说明 GNN 能够习得类似距离矢量的行为。Almasan 等 [10] 系统讨论了深度强化学习与图神经网络结合的路径优化用例。在仿真支撑方面，PRISMA [11] 提供了面向多智能体强化学习的包级路由仿真器。

与本文最接近的是 Alanazi 等 [12] 提出的 MANET 路由方案：采用集中训练、分散执行（CTDE）框架，每个节点用图神经网络对自身状态与邻域做消息传递以形成状态嵌入，用 DQN 选择下一跳；观测包含节点位置、队列长度与链路质量，奖励按"送达 +1、丢弃 −0.1"设定；为获得多跳感知，节点在 Hello 消息中搭载并交换各自的嵌入，训练离线完成、执行时完全分散。

### 7.3 两跳信息的利用

两跳信息在传统协议中早有应用。OLSR [5] 通过 Hello 交换让每个节点掌握两跳邻居集合，并据此选择最小多点中继集以压缩广播；T-Hello [14] 把信标交换扩展到两跳，使节点不必等待超时即可感知邻居移出范围；面向无线传感网的 NSI 方法 [15] 让节点在转发时同时参考下一跳及其下一跳的剩余能量、队列与链路质量。但这些工作使用两跳信息的目的分别是广播优化、邻居表维护与前向决策，**并未把两跳状态组织为可供图神经网络使用的节点—边特征结构**。

### 7.4 与本文的关系（一览）

| 已有工作 | 观测 | 动作 | 多路径 | 两跳信息 | 学习框架 |
|---|---|---|---|---|---|
| DSDV [1]、HMP [3]、MDSDV [4] | 路由表条目（跳数、下一跳，HMP 另含剩余带宽） | 固定规则取一条路径 | 有（HMP/MDSDV） | 无 | 无（规则式） |
| AOMDV [2] | 逐跳反向路径 | 固定规则取一条路径 | 有（按需发现） | 无 | 无（规则式） |
| Mai 等 [6] | 队列长度、邻居数、已服务包数、平均等待时间（一跳，固定图） | 离散选择唯一邻居 | 无 | 仅一跳 | 多智能体 PPO（参数共享） |
| Ding 等 [7] | 本地队列、邻居队列、邻居链路利用率 | 取 Q 值最大的邻居 | 无 | 仅一跳 | 独立 DQN |
| GAPPO [8] | 图拓扑编码 | 逐跳选择 | 无 | 未明确 | PPO |

| **本文（拟）** | 协议侧组织：6 维节点特征 + 4 维**跨层**边特征，**恰好两跳**，含多路径候选 | **对各候选下一跳的流量分配比例** | 有（协议被动维护，作为动作空间） | **直接测量的两跳节点与边特征** | 改进 MAPPO（差分奖励 + 拓扑感知图价值网络） |

### 7.5 现有工作的局限

**局限一：观测以节点自身的少量标量为主，缺少链路层面的显式刻画。**
[6] 的观测仅含队列长度、邻居数、已服务包数、平均等待时间；[7] 含本地队列、邻居队列与邻居链路利用率；[12] 含位置、队列长度与链路质量。这些量足以回答"往哪个方向走"，但不足以回答"经由哪条链路走"——相同跳数的两条路径，其物理层质量、介质访问层交付率与该邻居在路由表中的稳定程度可能差别很大，而上述工作中这些信息并未被完整地、以链路为粒度地提供给策略网络。

**局限二：观测与底层路由协议脱节，多路径结构没有被用作决策依据。**
[6] 在固定的图结构上学习；[12] 虽在真实仿真器上训练，其观测来自节点自身状态与邻居嵌入，并未利用路由协议维护的多路径结构；[7] 所描述的方法中也没有涉及多路径信息。而[2][3][4] 虽然维护了多条路径，转发规则却是预先设定的。也就是说，**"维护多路径"与"用学习决定如何用多路径"这两件事目前是分开的**。

**局限三：动作粒度是"选一条路"，无法按比例使用多条路径。**
[6] 为离散邻居选择，[7] 为取 Q 值最大的邻居，[12] 为在邻居集合与"保持"之间选择一个动作。当网络中确实存在多条可用路径时，这种动作形式无法表达"主路径承担大部分流量、备份路径分担其余流量"的调度方式。

**局限四：多跳感知依赖嵌入交换，而非直接可测量的邻域状态；观测范围与网络深度也未必对应。**
[12] 使用三层消息传递以获得多跳感知，但多跳信息来自节点之间相互搭载、交换的嵌入向量，属于"计算结果的传播"；[6] 则只使用一跳邻居。与此同时，两跳信息在 [5][14][15] 中已被证明有实用价值，却未被组织成图神经网络可以直接消费的节点特征与边特征。

**局限五：协作学习的信用分配与价值估计与目标不够贴合。**
[6] 的奖励为全局吞吐量与局部转发量之和，[12] 的奖励为全网统一的送达/丢弃信号。多节点共享同一全局信号时，不承担中继的节点与承担大量中继的节点会获得相同的学习反馈，不利于形成分工明确的协作策略。此外，[12] 的价值网络以节点嵌入与目的地址为输入，其价值估计建立在单个节点的嵌入之上，而非对整张图的图级聚合，难以体现"拓扑结构本身及其扰动"对长期回报的影响；据本项目前期的文献梳理，将图级聚合的价值估计用于多路径路由调度的工作尚不多见。

**局限六：对定位或集中式视图的依赖。**
[12] 的观测包含节点位置，[13] 依赖 GPS 以限制泛洪区域，[14] 依赖位置信息。位置信息需要额外硬件且在室内或受扰环境下未必可靠；而集中式全局视图与自组网的分布式本质并不一致。

### 7.6 局限与本文研究问题的对应，以及本文定位

| 既有工作的局限 | 对应研究问题 | 本文的应对 |
|---|---|---|
| 局限一：观测缺链路粒度、缺少跨层刻画 | RQ1 | 边特征按物理层、MAC 层、网络层、路由层四层分别采集，共 4 维，显式刻画链路 |
| 局限二：观测与协议脱节，多路径未被用作决策依据 | RQ1、RQ2 | 观测直接由协议状态组织；多路径候选集合直接作为动作空间 |
| 局限三：动作是"选一条路" | RQ2 | 动作改为对各候选下一跳的流量分配比例 |
| 局限四：多跳感知依赖嵌入交换，观测范围与网络深度不一定对应 | RQ1 | 两跳节点与边特征由状态广播直接获得，无需嵌入交换；观测范围与两层感受野严格对应 |
| 局限五：信用分配与价值估计不够贴合协作目标 | RQ3 | 引入差分奖励改善信用分配；引入拓扑感知的图价值网络改善价值估计 |
| 局限六：依赖定位或集中式视图 | RQ1 | 只用协议栈内可测的量，不依赖定位；执行阶段完全分散 |

**本文的定位。** 在主动式路由协议与图神经网络策略之间，建立一条"协议状态 → 结构化图观测 → 多路径流量分配"的完整通路，并在多智能体学习框架中针对协作调度做信用分配与价值估计两方面的改进。据项目前期的文献梳理，现有工作较少系统地从协议侧出发设计面向图神经网络的观测，也较少把多路径候选集合作为学习策略的动作空间。

## 八、预期贡献与后续计划

### 8.1 预期贡献

1. **一种协议驱动的两跳结构化图观测机制。** 把主动式路由协议的路由表状态、邻居状态与跨层链路状态，统一映射为以节点为中心的图观测，并使其范围与策略网络的感受野严格对应；观测不依赖定位信息，也不依赖集中控制器或嵌入交换。
2. **一种以多路径候选为动作空间、以流量分配比例为输出的图策略。** 使路由决策从"选择一条路径"变为"按比例使用多条路径"，并具备对节点数与拓扑变化的适应性。
3. **面向协作调度的学习框架改进。** 在多智能体 PPO 框架下引入差分奖励以改善信用分配、引入拓扑感知图价值网络以改善价值估计，使各节点的学习信号更贴近其边际贡献。
