# 工作流程规范

## 核心原则

**每个任务执行前必须确认，执行后必须汇报验收。未经确认不得开始执行，未经验收不得进入下一个任务。**

---

## 任务执行流程

### 第一步：任务预告（执行前）

每次开始新任务前，必须向用户明确报告以下内容，**等待用户确认后才能开始执行**：

```
【任务预告】Task X.X：任务名称

📌 目标：本次任务要达成什么
📋 约束：技术限制、环境要求、不能做什么
📦 交付物：完成后产出什么（文件、截图、日志、验证结果）
✅ 验收标准：用户如何判断任务完成

请确认是否开始执行？
```

### 第二步：执行任务

- 严格按照确认的目标和约束执行
- 不做超出范围的事情
- 遇到问题立即暂停并向用户报告，不自行决定绕过

### 第三步：执行汇报（执行后）

任务执行完成后，必须向用户提交详细报告，**等待用户验收通过后才能进入下一个任务**：

```
【执行汇报】Task X.X：任务名称

✅ 完成情况：
  - 具体做了什么
  - 产出了什么文件/结果

📊 验证结果：
  - 运行了什么验证命令
  - 输出是什么
  - 是否满足验收标准

⚠️ 问题与备注：
  - 执行中遇到的问题及解决方式
  - 需要用户注意的事项

📁 交付物清单：
  - [ ] 文件1
  - [ ] 文件2
  - ...

请验收。
```

---

## 禁止事项

1. **禁止跳过确认**：不得在未向用户报告任务内容的情况下直接开始执行
2. **禁止连续执行**：不得在一个任务完成后未经用户验收就自动开始下一个任务
3. **禁止超范围执行**：不得做用户未确认的工作
4. **禁止隐瞒问题**：执行中遇到异常或偏离预期的情况必须立即报告
5. **禁止自行决策重大问题**：遇到需要技术选型或方案变更时，必须列出选项供用户决定

---

## 任务状态跟踪

每个任务的状态需要在对话中明确标注：

| 状态 | 含义 |
|---|---|
| `PENDING` | 待确认，尚未开始 |
| `CONFIRMED` | 用户已确认，准备执行 |
| `IN_PROGRESS` | 正在执行 |
| `REPORTED` | 执行完毕，等待用户验收 |
| `DONE` | 用户已验收通过 |
| `BLOCKED` | 遇到问题，暂停等待指示 |

## 示例流程

```
助手：【任务预告】Task 1.1：ns3 环境搭建
      目标：...
      约束：...
      交付物：...
      验收标准：...
      请确认是否开始执行？

用户：确认

助手：【执行汇报】Task 1.1：ns3 环境搭建
      完成情况：...
      验证结果：...
      交付物清单：...
      请验收。

用户：通过

助手：Task 1.1 已完成（DONE）。接下来是 Task 1.2，是否继续？
```
